# 7. MVVM STANDARD

Adopt a consistent MVVM strategy.

Preferred structure:

```text
View
 |
 v
ViewModel
 |
 v
Service / Application Layer
 |
 v
Domain / Core
```

Views should primarily handle:

* presentation
* bindings
* visual states
* UI events that genuinely belong to the View

ViewModels should handle:

* presentation state
* commands
* orchestration
* validation
* interaction with services

Services should handle:

* media operations
* file operations
* project operations
* rendering
* exporting
* persistence
* application infrastructure

Do not put substantial business logic in XAML code-behind.

# 12. ASYNC AND THREADING

Audit all asynchronous operations.

Media processing, file operations, rendering and exporting should not block the UI thread.

Avoid:

```csharp
.Result
.Wait()
```

where asynchronous alternatives are appropriate.

Ensure cancellation is supported for long-running operations.

Use:

```text
CancellationToken
IProgress<T>
async/await
```

where appropriate.
